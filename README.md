# 短剧切片工作台（dsh-duanju-slice）

给短剧运营用的自动化剪辑工作台：给定**剧本 DOCX + 剪映工程目录 + 成片保存目录 + 一个内容方向**，
自动在剧本里找到该方向的精彩片段、在工程里用字幕定位到时间码、抽首尾帧核对，最后产出

1. 一条**可编辑的剪映草稿**（画面 / 字幕 / 音频，直接出现在剪映草稿箱里，可继续调整）
2. 一条**成片 MP4**（原画面 + 对白 + 烧录字幕 + BGM/音效，导出到你指定的目录；末尾接与短剧剪辑插件相同的片尾）

一个会话可以持续讨论、生成和修改。每次生成一个新版本，保留旧版和原工程。

## 环境要求

| 依赖 | 说明 |
| --- | --- |
| 剪映专业版 | 本机实测 11.6.0（macOS）。工程目录里每集是一个 `EPxxx-副本` 草稿文件夹 |
| FFmpeg / FFprobe | 依次取插件配置、`DUANJU_FFMPEG`/`FFMPEG_PATH`、同机已装的短剧剪辑插件便携运行时、系统安装，最后才是 PATH 里的 `ffmpeg` |
| 字幕字体 | 插件自带 `TikTok Sans Display Dark Bold`（`assets/fonts/`），可在配置里换 |

## 使用

1. 左侧栏点「切片工作台」。左侧默认显示220px的会话列表，列出名称、更新时间、当前片段和版本；点击切换。列表可收起，顶部「会话列表」按钮可重新展开，当前会话高亮。窄窗口使用抽屉，选中后自动收起；只有点「新建会话」才创建独立对话，新会话继承素材路径，方向留空。
2. 新会话选择剧本 DOCX、剪映工程目录、保存目录并填写方向，然后点「确认并锁定配置」。确认前可以修改，确认后本会话不能更换这四项设置；需要不同素材或方向时新建会话。
3. 锁定不会自动生成视频。主区显示只读配置摘要、视频预览和聊天，不再提供「修改配置」。可以先讨论选段，也可以点预览区「生成初版」。
4. 同一对话中说「保留前25秒，背景音乐减半」「向前多留两秒」可修改当前选中版本；说「换个片段」可在固定素材/基础方向内重新选段。每次生成新草稿和MP4，保留旧版。
5. 预览区显示当前版本，底部小工具栏提供文件入口。多版时可切回旧版，也可在对话里说「回到V1」。修改失败保留上一版。素材、保存目录和基础方向在后台同样受锁定保护，不能通过对话绕过。
6. 确认锁定后自动展开聊天，仍可随时收起；会话历史和剪辑版本持久保存，重开后继续。旧的已制作会话按已锁定处理；新会话继承素材路径，方向留空，并且需要重新确认。
7. 页头「打开剪映」可启动或唤起本机Mac上的剪映专业版。新草稿需在**重启剪映**后刷新草稿箱。大于宿主32 MiB完整读取上限的MP4使用本机播放器查看。

对话中的裁剪时间相对当前版本开头；省略首尾或音量时沿用当前版本。对白、BGM和音效倍率相对原工程，0静音，1原音量，最多4倍。「再减半」按当前倍率计算。原集不够长或不足1秒的区间会拒绝执行。

移出会话列表只影响工作台目录，对话、成片和草稿文件都会保留。

方向写法没有固定枚举：想多要钩子就给带钩子描述的方向，素材撑不住时 AI 会按素材实际内容选最贴近的一段。

## 集数识别（扁平草稿箱）

剪映草稿箱是**扁平目录**：所有草稿都在根目录下，草稿箱里看到的「肥胖女星」这类分组是剪映的**本地草稿虚拟文件夹**，名字只写在配置里，磁盘上没有同名目录；导入的草稿文件夹还常叫「10月13日 (1) (1)」「2-副本」这种名字。所以找集按三层来，三层结果**合并**报告：

1. **文件夹名自带集号**：`EP007-副本`、`7`、`7（1）`，以及整目录导入常见的 `2-副本`、`25-副本-未剪`、`4-副本1`。
2. **剪映虚拟文件夹成员**：读 `LocalDraftFolder/folder_meta_info.json`（分组名）和 `draft_folder_mappings.json`（分组 ↔ draftId），按草稿自己的 `draft_id` 认出成员。
3. **草稿素材文件名**：分组 id 对不上时（草稿从别的电脑导入，`draft_meta_info.json` 已被加密），从草稿自己的素材库/明文时间轴里读 `EP002.mp4` 这类文件名定集号。

本插件自己产出的切片（`…_v1_20261116054226_678c90fe` 这种名字）不会被当成可剪的集。

### Windows：先按剧名落到剪映分组，再回草稿箱找成员

剪映「本地草稿」的分组（草稿箱里看到的「肥胖女星」文件夹）不是磁盘目录，只登记在
`%LOCALAPPDATA%\JianyingPro\User Data\Config\LocalDraftFolder\`。所以现在的顺序是：

1. 读 `folder_meta_info.json`，按**剧本剧名**匹配分组（去掉 `cut-` 前缀后做包含匹配；`duanju_slice_*` 也可用 `drama` 显式指定）；
2. 读 `draft_folder_mappings.json` 拿到这一组登记的草稿 id 和份数；
3. 回你给的工程目录里认这些成员草稿：
   - 先按草稿自己的 `draft_id` 对（本机原生草稿能对上）；
   - 导入稿的 `draft_id` 被剪映加密读不到时，按**草稿文件夹创建时间 ≈ 分组创建时间**对齐，并且**只有候选数量与分组登记份数完全一致才采用**（实测：`cut-肥胖女星` 3 份、`cut-掌权先知` 47 份都精确命中，窗口 ±5 秒）；
4. 只在这些草稿里选集、出方案。分组对不上（剧名不匹配、或份数对不上）就报错说明，不会去剪别的剧。

匹配不到分组时不套这层（例如只给了某个草稿箱目录里的散草稿），改走下面的混剧保护。

### 一箱混着多部剧时不会猜

同一部剧导入后通常共用一种命名（`N-副本` 一族 / `EPxx` 一族 / 日期名一族）。如果没匹配到剪映分组、草稿箱里又同时出现多族，插件不会自己猜：

- 自动流程会停下来报错，列出每一族有多少份、覆盖第几集、以及示例文件夹；
- 这时用 `drafts` 指定这次要用的草稿文件夹（可只写名字的一部分，如 `["10月13日"]` 或 `["-副本"]`），插件就只在这些草稿里选段；
- 也可以把一部剧的草稿单独放一个工程目录，自动流程就会正常放行。

`drafts` 里写了不存在的名字会直接报「没有匹配项」，不会退回到全箱猜。

配置目录默认取 `%LOCALAPPDATA%\JianyingPro\User Data\Config\LocalDraftFolder`，可用环境变量 `DUANJU_JIANYING_CONFIG_DIR` 覆盖（测试用）。勘察报告会写明本次用的是哪几层、剪映里有哪些分组、每一族草稿各多少份。同一集有多份草稿时，能读出明文时间轴的那份排在前面。

## 成片片尾

成片 MP4 在剧情结束处不直接结束，而是接上与短剧剪辑插件完全相同的收尾：

- **时停**：取剧情结束前 1.5 秒的那一帧（成片实际画面，含画中画与已烧字幕）定格，保持到音效结束。
- **结束特效**：剪映原生「炫光」转场（资源 6726707814028284423），默认 0.8 秒，从剧情结束前 0.4 秒开始、跨过结尾；画面按该资源的 23 帧光效序列与同一 screen 混合公式合成，不用自制光效替代。
- **结束音效**：剪映原生「大气片尾声效」（资源 7023776340713164069）整段完整播放，不裁剪、不淡入淡出；剧情原声、BGM、音效音量不变。

片尾新增时长约等于「音效时长 − 转场的一半」，向上取整到整帧（默认音效 4.584 秒，约 +4.2 秒）。资源随插件内置在 `assets/ending/`，缺失时按剪映本地缓存兜底，仍找不到会报错而不是换成别的素材。

成片和剪映草稿用的是同一套片尾：草稿末尾同样有定格照片、原生「炫光」转场和独立音效轨，草稿总长 = 成片总长，剪映里直接导出应与成片一致。临时文件放在成片同目录的 `.slice-tmp-*` 下，渲染结束即清理。

## 输出的草稿

- 位置：剪映 `currentCustomDraftPath`（默认 `~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft`），目录名含剧名、集号、版本号与唯一后缀。
- 只保留画面、字幕、音频三类轨道；为保留画中画与重叠混音，每类可以有多条轨道。片头封面卡、名片卡、贴纸、特效、转场、集数卡字幕都会被去掉。
- 字幕保留原工程文本与时间码，字体统一；位置按参考图固定为水平居中、字幕中心在画面高度78%处。可编辑草稿和MP4共用此位置，单行和双行都以字幕中心定位，随分辨率换算。草稿根目录写的是明文 `draft_info.json`，剪映打开后会自己转成加密格式并重算时长。
- 每条切片写入独立草稿/时间线身份、当前创建时间和实际时长，避免沿用原集元数据而排到旧草稿里。剪映运行中生成后，需要重启后刷新首页。
- **素材自包含**：生成时把时间线实际引用的素材收进草稿自己目录，并把 `path` 改写成草稿内绝对路径——本集素材沿用整目录复制（不重复占空间），散落在别的草稿目录里的素材拷到 `materials/_slice/`。这样换电脑或直接打开新草稿都不会弹「链接媒体：检测到以下媒体丢失」。
- 原工程本身缺文件的片段会从草稿里去掉（结果里的 `media.missing` 列出缺口），指向 Windows 缓存特效/蒙版的不存在路径会清空，让剪映用默认效果；没有被任何片段引用的素材不会写进草稿。

## 命令行（不开 DSH 也能跑）

```bash
node scripts/survey.mjs <工程目录> [剧本.docx]                       # 只读勘察：可用集数、字幕数、缺素材
node scripts/locate.mjs <工程目录> <剧本.docx> "方向" --episode 40 --lines 3-8 --frames /tmp/frames
node scripts/slice.mjs  <工程目录> <剧本.docx> --episode 40 --lines 3-8 \
  --direction "复仇向：当众揭穿继母" --render <导出目录> [--draft-root <草稿箱>] [--frames <抽帧目录>]
```

## 已知限制

- 草稿箱里有些 `EPxx-副本` 是「0 字幕 / 只有两张图」的骨架草稿，不会被当成可用集。
- 工程内嵌的复合片段会展开并映射画面、对白与时间码；父级复杂蒙版和特效不重建，成片沿用硬切导出规则。
- 有独立对白音轨的时间段，底层视频原声会静音，避免重复人声；未覆盖部分保留视频原声，BGM和音效保留。相同规则写入可编辑草稿和成片。
- 字体只有拉丁字形，中文字幕会回退到系统字体。
- 原工程本来就缺的素材（常见是 BGM/音效 mp3）不会凭空补出来：草稿会少那条片段，成片也少那条声音，画面和对白不受影响；缺口见结果里的 `media.missing`。
- 剪映 11.5 会把草稿重写成自己的加密格式；重启剪映后草稿列表才会刷新，若列表时长仍是整集，说明这份草稿还没被重新读取（旧版遗留），重跑一条即可。
- 同名草稿目录已存在时直接报错，不覆盖。

## 目录

```
index.js           宿主侧：勘察 / 选段 / 生成 / 修改 / 版本切换工具 + 工作台命令
client.js          工作台界面（侧栏入口 + 设置页 + 内嵌对话）
lib/draft.js       读剪映草稿明文、字幕与轨段解析
lib/locate.js      台词↔字幕匹配、切点吸附到帧
lib/pick.js        让模型按方向选段
lib/plan.js        整条方案编排（勘察→选段→定位→首尾帧）
lib/slice-draft.js 克隆工程并裁剪成切片草稿（含素材自包含）
lib/ass.js         字幕排版（中英混排换行）
lib/render.js      FFmpeg 成片渲染（画面拼接 + 混音 + 烧字幕 + 片尾）
lib/ending.js      片尾：时停取帧、原生炫光帧序列、大气片尾声效混合
lib/studio.js      会话设置、版本历史、每轮上下文与工作台命令
lib/revision.js    基于选中版本计算裁剪区间与音量
assets/ending/     内置片尾素材（大气片尾声效.mp3 + 炫光转场资源）
scripts/*.mjs      命令行入口
```

## 界面回归检查

使用宿主已有的 React / ReactDOM，无新增运行依赖。例如本机：

```bash
DSH_REACT_ROOT=../build/ssr npm test
```

`DSH_REACT_ROOT` 指向可以解析 `react` 和 `react-dom/server` 的 Node 项目；若当前项目已能解析 React，可直接 `npm test`。测试的进度文件全部写入临时目录，不读取或修改用户真实任务。

### 导入剪映时的三个坑（0.1.6 起已处理）

1. **剪映 11.5 读新版正文文件**：只写 `draft_info.json` 时，剪映显示和打开的是复制过来的整集。现在 `draft_info.json`、`draft_content.json`、`template.json` 三份都写成同一份切片时间线。
2. **草稿名过长**：剪映会按自己的长度上限改写超长草稿名，草稿里写死的绝对素材路径随之全断（「媒体丢失」）。现在草稿名控制在 20 字以内 + `_v版本_短码`，不再带长方向描述。
3. **素材库清单不全**：素材已全部收进草稿目录，素材库和虚拟素材表也按实际引用的素材重建（视频/照片/音频都算），打开不应再提示重新链接。
