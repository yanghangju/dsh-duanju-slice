# 配置自动剪辑工作台运行环境

仅处理自动剪辑工作台发来的环境配置请求。用户在同一配置对话里说「请继续配置运行环境」或要求重试时，沿用工作台之前发来的配置请求 ID，不要求用户点击按钮或重新提供 ID。若该对话从未收到工作台请求，不安装任何东西。本会话不执行剪辑。

用通用 Shell 工具运行本 Skill 目录内的 `setup.mjs`，唯一参数是该请求 ID。脚本先检查并复用本机 Python 和卡点依赖、FFmpeg、FFprobe；缺失时用内置下载源补齐工具和默认曲库。代理或首选来源失败时，脚本会自行尝试直连、备用下载入口或其他内置软件源，在这些途径都试过后再报错。不要改系统代理、绕过完整性检查、下载到脚本以外的位置或自行从任意网址下载安装包。

- Windows 用 `pwsh`。把下面的脚本路径替换为 Skill 资源目录中的绝对路径，保留单引号；把 `REQUEST_ID` 替换为请求里的 ID。

  ```powershell
  $node = $env:DSH_NODE_EXECUTABLE
  if ($node) { $env:ELECTRON_RUN_AS_NODE = '1' } else { $node = 'node' }
  & $node 'C:\绝对路径\setup.mjs' 'REQUEST_ID' | Write-Output
  exit $LASTEXITCODE
  ```

- 其他平台用 `bash`：`ELECTRON_RUN_AS_NODE=1 "${DSH_NODE_EXECUTABLE:-node}" '/绝对路径/setup.mjs' 'REQUEST_ID'`。缺少工具时脚本会说明平台限制。
- 用 Shell 的后台任务模式（`run_in_background: true`），等待并获取最终任务输出再答复；仍在运行不算完成。如果 Shell 沙箱阻止写入本机配置目录或启动安装子进程，按 Shell 自身的审批流程，仅对这条原命令申请所需权限，不绕过审批。
- 仅在脚本退出成功且输出 `ready: true` 时告知配置完成。工作台会自动验证并显示「新建会话」。
- 首次失败先读最终输出，区分临时网络问题、本机依赖问题和授权问题。若还有安全可行的处理办法，先处理再用同一 ID 续跑一次，例如确认配置的 Node 路径失效后改用本机已安装的 `node`；不因首选下载失败就停下来，也不原样循环重跑。不忽略校验失败，不绕过拒绝或取消。
- 若安全途径都已用尽，说明卡在哪一步、已尝试什么和下一步。普通失败不会耗掉请求 ID；用户随后在同一对话明确要求重试时，用原 ID 继续。只有原请求已不可用且不能恢复时，才请用户在工作台重新发起。
