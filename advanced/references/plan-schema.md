# 剪辑方案

> 改编自 NarratoAI duanju-promo，沿用下文所述音乐分析与同步逻辑。安装包的 JSON 入口与正文契约见[执行契约](<../runner-contract.md>)，不读取外部 Skill。最终片尾和草稿由本安装包的 Node 桥完成。

成片总时长不超过 50 秒，包含所有对白、快切、黑屏、转场和定格；总长按正文与固定片尾相加计算，并核对实际媒体时长；按 [固定片尾](<ending.md>) 的实测完整音效时长提前预留，不能靠截短片尾或硬截对白满足 50 秒。已有方案的快切镜头数由 N 增至 2N，快切累计仍为 5–10 秒；计划记录原数量与新数量，新任务无旧方案时说明实际数量与密度，不虚构基数。

## 内部取材与单一执行方案

`proposal` 接收 `{title, story, segments, base_montage_count?}`。按预计顺序写清每段的 `episode/kind/purpose/seconds/visual/transition/audio`，对白加 `source_line_id/quote_zh`，非对白加唯一 `shot_id`。字幕与剧本语言不同时，如有可用 `.srt` 中的对应完整原句，可加 `subtitle_quote`；ASR 未匹配时可按下文从实际转写补 `asr_quote`。先读原稿，不编造已核实的画面或时间码。正式剪辑的 `proposal` 只保存内部目标，立即继续。仅「只出方案」模式写 `{...proposal,plan_only:true}` 为 `tmp/plan.json` 后结束，不定位或渲染。

任务途中可基于真实素材删、替、增或重排。新增或更换对白用 `proposal → locate`，无需新目标的调整直接 `save_plan → sync → validate → render`。`tmp/plan.json` 保留实际剧情、镜头及顺序、源范围、音乐与片尾。渲染从此文件读取，不另写 Word。

## 自动对白定位结果与回填

正式任务提交内部目标后立即 `locate`。优先用同集可用 `.srt` 的完整字幕条时间；缺字幕、字幕无效或不可用、未可靠匹配完整台词时，自动用 Slice 语音识别定位未命中的台词，不询问用户、不改已有字幕锚点。未选字幕目录则直接用语音识别。两路命中后都在锚点附近以 5 fps 看帧验收完整动作及切镜，动作不确定不通过，见[台词定位与画面核验](<visual-alignment.md>)。

定位目标取 `task.executionProposal ?? task.proposal`；`tmp/dialogue-alignment.json` 的 `segments` 只含已验收对白，不是最终 `plan.segments`。`segment_index` 是定位目标里的 0 起始段位，不随剪辑顺序改号。对白项原样引用，证据绑定当前目标、集数、精确引文、字幕或语音起止与完整画面边界；不得改句、裁句、借用别句证据或用手工采样替代对白定位。

定位 `incomplete` 时保留诊断，可用已通过的条目并重试缺项，或换成可用内容继续。若 ASR 已取得转写但未匹配剧本台词，从返回的 `alignmentFile` 读取 `sources[].asr.transcriptFile`，找到同一句完整原文才填可选 `asr_quote`（已有 `subtitle_quote` 也可作为 ASR 同语提示，不是字幕证据）；直接 `proposal → locate` 复用转写缓存，不手填时间。`force:true` 才整体重跑；已通过的对白直接复用。`montage/picture/continuation` 不抽帧、不填 `visual_review`，按剧本与已定位素材选取。

## 执行用 plan.json

`plan.json` 顶层：

| 字段 | 内容 |
|---|---|
| `title` | 独立草稿名称；导出时自动追加时间，避免覆盖 |
| `story` | 可选，按实际采用内容记录人物、冲突、转折与钩子，不冒称未使用的原剧情已呈现 |
| `segments` | 按最终播放顺序排列的实际片段，可删、替、重排或增加；对白须绑定真实定位的精确引文与完整边界 |
| `audio` | 可选的本地背景音乐与音效，不含合成旁白 |
| `music_cues` | 可选的自然落差黑屏、主动卡点黑屏及同步静音、末句后重击，见下文 |
| `notes` | 叙事目的、参考结构、实际检查和限制；记录固定片尾的 E、取帧集数/源时间、音效完整时长、转场/音效起点、BGM 截止与最终总长，实际执行参数使用 DSH 返回的 ending 描述 |

普通片段：`episode` 是索引中的集号；`start/end` 是该集原片的绝对秒数；`kind` 为 `dialogue`、`montage`、`picture` 或 `continuation`；`volume` 为原声音量，0–2，默认 1。`picture` 表示快段以外的单个静音画面，必须显式 `volume: 0`，例如铺垫中的较长动作或反应镜头；有原声的台词仍须按对白验证，不用于伪装快切，也不能替代快切后须立即衔接的原声剧情高潮。

对白另外记录：

```json
{
  "episode": 1,
  "segment_index": 0,
  "start": 1.2,
  "end": 4.8,
  "kind": "dialogue",
  "source_line_id": "E1L1",
  "quote_zh": "原稿中选取的完整句子",
  "volume": 1,
  "alignment": {
    "method": "video-frames",
    "reviewer": "llm-batch",
    "reviewed": true,
    "complete": true,
    "start": 1.2,
    "end": 4.8,
    "dialogueEnd": 4.6,
    "asr_anchor": { "start": 1.21, "end": 4.58, "text": "模型识别文字", "quote": "原稿中选取的完整句子", "score": 1, "timing": "utterance" },
    "ending": "shot-cut",
    "postDialogueCut": 4.8,
    "confidence": 0.9,
    "sampling_file": "<locate返回的本任务持久化采样清单绝对路径>",
    "evidence": "批量视觉请求核实的人物、场景、动作或切镜证据"
  }
}
```

上例是单条 ASR 锚点的对白。每条对白按实际来源只带一种锚点；字幕命中用 `alignment.subtitle_anchor`，包含同集 `file`、`sha256`、`cueIds`、`start/end/text/quote/score` 和 `timing: 'cue'`。同集对白可混用两种来源。直接引用本任务 `locate` 已验收的完整条目和 `alignment.sampling_file`，保留实际返回的 `subtitle_quote` 或 `asr_quote`（如果有）。不能用示例时间码、伪造清单，或把采样成功当作验收。跨窗证据须连续覆盖完整 `[start,end]`。

`montage/picture/continuation` 不再需要画面证据：不填 `visual_review`、不引用采样清单，按剧本与已定位素材选取，使用唯一 `shot_id` 并填写 `purpose/visual/transition/audio`。`continuation` 保留完整原声动作且 `volume:1`，`picture` 和 `montage` 原声为 0。实际使用的原声台词须通过 `proposal → locate`，不伪装成非对白。

蒙太奇用 `kind: montage, volume: 0`，只安排一组连续快切，所有快切镜头累计为 5–10 秒，已有方案时使用原数量两倍的不同画面，记录原数量、新数量、画面内容与选择理由；不靠重复或拆分同一连续画面充数。允许在选定快切区间内主动叠加短黑屏及同步静音以强化音乐卡点，黑屏计入快切总长（5–10 秒），不增加时间线长度；黑屏本身和被全黑覆盖的段均不计作有效画面镜头。快切后立即接同一故事线中最激烈的原声剧情高潮：有台词用 `dialogue`，无台词的完整原声动作片段可用 `continuation`，不能直接定格或接静音占位画面。程序检查时长与原声衔接，高潮强度由 AI 结合实际执行剧情与画面验收。源视频的硬字幕会保留；静音快切不冒充完整原声对白。

固定片尾按 [ending.md](ending.md) 独立执行，正文 `segments` 不再追加旧式 `kind: freeze`。时停取正文终点 E−1.5 秒所对应原片帧，生成 PNG；从 E 开始保持到完整片尾音效结束并向上对齐 30 fps。本任务原生「炫光」T 秒（默认 0.8，由 `endingTransitionSeconds` 或任务记录决定，范围 (0,10]）与完整「大气片尾声效」从 E−T/2 秒同时开始，正文完整保留至 E；末段和正文总长须容得下 T/2。旧式 `freeze/flash` 只说明旧执行器能力，不能替代本版强制的原生照片和转场；原 CLI 未实现该原生片尾，须按引用流程复用 DSH 函数完成。

配乐项：`file` 是已有本地音频绝对路径；`start` 是成片时间；`duration` 为长度；`source_start` 默认 0；旧式线性 `volume` 默认 1；`fade_in/fade_out` 是淡化秒数；`name` 为轨道显示名。原片自带音乐不会被自动分离。配乐与片尾音效保留为剪映独立音轨，可继续调节。

音轨必须标角色。`role: bgm` 的 `volume_db` 统一为 −5，线性 `volume` 为 `10 ** (-5 / 20)`；插件保存、同步及渲染时都会归一化，不接受用户音量覆盖。这是轨道基础增益，不是整片响度或峰值；淡化与总线防削波限幅另计。`role: sfx` 保留自己的 `volume` 或 `volume_db`。

`music_policy` 使用 `single_song: true`、`song_sha256: <beats.json的file_sha256>`、`bgm_db: -5`。执行器检查所有 BGM 的文件内容属于同一首歌；不同复制路径可具有同一指纹。原声段已有的片内音乐不自动分离。

正文使用同一首原速 BGM；固定片尾时，BGM 按 DSH `finishMusicBefore` 在片尾音效实际起点 E−T/2 秒前淡出并截止，仍使用本任务基础增益。原声完整保留到 E，片尾指定音效保持音量 1、无淡入淡出并完整播放。`preserve_audio: true` 的持续到全片末尾约束不适用于固定片尾交接，执行时省略或设为 `false`；原音乐文件保留，黑屏静音只处理已授权范围。

执行器拒绝无音轨的原声对白、越过源音频长度的配乐区间及无效淡化参数。成片和草稿统一为 1080×1920；渲染分段统一BT.709与limited色阶，避免JPEG定格和视频拼接后黑位转换不一致。9:16 原片保留可调整的原始截取范围，其他画幅先生成等比留边的正式分段素材，包含该段已设音量，避免依赖编辑器默认缩放。此类分段在剪映中以音量 1 为调整基准，不重复衰减。

剧情高潮完整结束后，必须接上述原生转场、独立完整片尾音效和 E−1.5 取帧的照片时停，片尾后不能再接正片、字幕页或其他画面。`continuation` 可用于已核实的原声高潮动作及同主线必要前后动作补齐，不代表尾接完整一集。

## 音乐卡点

方法参考 [AI Montage Agent 的音乐分析](https://github.com/zhangzhanglaila/ai-montage-agent/blob/0a010202e2ede7c9b2e20e06d10520942e84a44c/packages/montage/beat.py)与[真实拍点同步](https://github.com/zhangzhanglaila/ai-montage-agent/blob/0a010202e2ede7c9b2e20e06d10520942e84a44c/packages/montage/sync.py)：用 librosa 检测节拍，以起音与 RMS 能量区分强弱，根据实际相邻拍点相减取镜头时长。本实现不采用上游的模拟拍点回退。

- `beats` 生成 `beats.json`，记录音乐源路径、SHA256、检测方法、真实拍点和强度。分析只涉及音乐节奏，不用于对白定位。
- `sync` 处理一组连续静音快切，目标总长为 5–10 秒；`--audio-index` 是待同步 BGM 在 `audio` 数组中的位置，默认 0。不能拆成多组规避总长上限，快切结束立即接原声剧情高潮。
- 正文沿用当前锁定的同一首 BGM；未成片时若整条选曲不合适，可重新 `select_music` 更换整首单曲并保留旧素材，再重新 `beats/sync/validate`，不在快切处混入另一首。先核实真实快节奏段的进入、结束与长度，按音乐确定 5–10 秒快切时长，不固定套 5 秒或 10 秒。快段在此范围内时优先覆盖其完整起止；超过 10 秒时选其中 5–10 秒连续区间，在真实音乐事件处退出；不足 5 秒时寻找同曲其他合适连续快段，无合适范围时说明限制，不循环、变速或加黑屏凑足。`rhythm_sections` 的 8 秒统计仅用于找候选，不能作为精确段长；需结合真实起音、波形和打击能量定界，BPM 不变也可能因配器和细分节奏变密。
- `events` 包含 `major` 大重音候选和 `minor` 真实拍点/起音。大重音用高起音、能量上升与间隔抑制估计，属于音乐重击/变化线索，不等于已经人工听音确认的乐理小节第一拍。
- 音乐可从任意可用 `source_start` 开始。搜索同曲选段/起点时，先比较能命中的大节奏数量，再比较总命中数，不能让更多小拍挤掉大重音。成片事件时间为 `源事件 - source_start + audio.start`。修改音乐起点后重新同步，最终 MP4 与草稿使用同一映射。
- 在重要快切片段写 `music_end`，值为 `beats.json` 中真实事件的源音频绝对秒数，表示该片段结束后的落点。最后快切须标重要终点；其余镜头由优化器尽量匹配真实事件，不再只允许少量必卡点。
- 新分析默认使用 `hierarchical`：优先命中大重音，再增加真实小拍与起音命中。局部音乐越密，尽量用更多短镜头，例如约 0.25 秒一镜；相对舒缓处可约 0.5 秒一镜，示例不是固定网格。已有方案时镜头数由 N 增至 2N，总快切仍为 5–10 秒；不足时补充不同画面或重新选段，无法兼顾时说明限制，不降低目标数量或放宽时长。通过选镜数量与 `rhythm_weight` 设置相对长短，`min_duration` 默认 0.2 秒以保持可读性；不强行追每个小拍，无法命中时可自然切。
- `end` 是已确认画面的可用终点；`available_end` 可指定看帧核实的更长终点。所选快切区间为 5–10 秒，画面不足时补充不同镜头，或重新选取 5–10 秒的音乐区间、更新 `music_cues.fast_section` 与最后 `music_end` 后重新同步；不循环旧镜头，不在快切中换歌，不用变速、克隆末帧或黑场凑时长。不能改了音乐选段却沿用旧卡点。
- 对每个累计绝对边界按 30 fps 量化，再相减取段长；不能每段独立取整后相加。正文快切使用硬切，片尾使用规定的原生炫光；显式指定拼接段长，并将视频首个 PTS 归零，避免转场或 AAC 填充改变画面与音乐的相对时间。
- `beat_sync.mode` 为 `hierarchical`，`cuts` 记录实际命中的全部切点与 `level`，`major_hits` 记录大重音命中，`free_cut_count` 记录未命中的自然切点。验收优先报告大节奏覆盖，再报告总命中；每个声称命中的点都需核对真实编码和草稿时间。旧 `music-first`/全部卡点清单仍可读取。
- 读取旧方案的连续配乐片段时要保持源时间连续，并将 `beat_sync.audio_index` 更新为覆盖快切的音乐段。新渲染统一为 −5 dB；仅补做旧成片的草稿时沿用该片实际混入的增益。固定片尾交接按 `finishMusicBefore` 执行，BGM 不延续到片尾声效上；完整片尾音效结束前不得结束照片定格。
- 对白不为卡点修改。可变快切时长改变后，后续对白在成片中整体平移，源视频中的正文范围保持不变。 输入音轨时长按同步前的时间线填写；`sync` 会调整覆盖快切结尾的音轨时长（含所选 BGM），并移动后续音轨，保持高潮段及片尾配乐衔接。
- 不能只看方案数学结果：检查实际编码与草稿时间线；声称命中的事件误差不超过 1 帧。尽可能增加命中，但不破坏大节奏、完整对白或动作可读性；未命中处按视觉连贯验收。没有听音能力时仍须明确听感未验收。

## 音乐落差与最后重击

`beats.json` 的 `energy_envelope` 记录实际音频的 `step`（约0.02秒）与 `db`（各窗RMS dBFS）。相对能量落差不等于绝对静音；不能据拍点间隔伪造停顿。旧分析没有这些数据时，先重新运行 `beats`。

快切期间，AI 可依据实际重音、起音或节奏转折主动新增短黑屏并同步静音，无需原曲先有自然停顿或能量落差，也无需逐处另行确认。保留原曲与处理前分析，记录音乐事件、设计目的、源区间和成片映射；在选定快切时间线上叠加黑屏，黑屏时间计入快切总长（5–10 秒）及全片 50 秒，不能用来补素材或抵扣翻倍镜头数。先在原曲分析上确定对应源范围，再用 FFmpeg 的 `aeval` 逐采样条件滤镜制作正式无损 WAV 副本，保持源总时长、采样率与后续音乐位置不变；按半开区间 `[source_start, source_end)` 静音，到恢复点立即恢复。滤镜示例（仅示意源 1.0–1.4 秒，实际使用已确认范围）：`aeval=exprs='if(gte(t,1.0)*lt(t,1.4),0,val(ch))':c=same`，区间外保留各声道原采样；普通 `volume` 的音频块粒度可能使边界误差超过一帧。静音处理仅改 BGM 副本；快切原声保持 0，黑屏区间不叠加 SFX，确保实际成片同步静音。保留原曲和完整原声台词；黑屏不得越出快切区间遮住剧情，不插入额外黑屏段延长时间线。副本放在任务 `assets/` 中，重新运行 `beats`，`audio.file`、`music_policy.song_sha256`、`music_cues.analysis_file` 统一指向副本及其新分析，并重新 `sync`；`preserve_audio` 设为 `false` 或省略。成片与草稿都使用该副本（导入草稿时复制进草稿目录），不把静音处理留成只在播放器中生效的操作。

需要这些效果时，在顶层加入 `music_cues`：

- `audio_index`：对应的 BGM 下标。
- `analysis_file`：本任务 `beats.json` 的绝对路径；执行器核对音频路径与 SHA256。
- `fast_section`：快切方案必填对象，`source_start/source_end` 表示实际采用的快节奏区间，长度须为 5–10 秒，并随音乐实际快节奏段长度确定；范围内优先完整采用，更长时可取符合真实落点的局部，不足 5 秒不补时。填写 `reviewed: true` 与 `evidence`，说明原快段时长、节奏变化、所选范围及完整或局部取用。执行器核对一组连续 `montage` 与所选源区间的起止映射，误差不超过半帧，并校验源范围、方案快切总长及帧量化后范围均为 5–10 秒；最后快切的 `music_end` 等于所选 `source_end`，两端来自实际音乐事件。调整选段后须更新范围并重新同步；旧方案未填写本字段时，也须按新范围调整后通过验证。
- `blackouts`：可选数组。每项用 `source_start/source_end` 指定实际使用音频的落差起止，填写 `reviewed: true` 与具体 `evidence`；手动静音时写明人工处理范围与恢复点，能量证据来自静音副本，不声称原曲自然停顿。主动卡点黑屏须在 `evidence` 写明节奏依据，源范围映射后须位于所选快切区间内；无需原曲先有自然落差。执行器对实际使用的音频（主动静音时为处理后的副本）要求谷底比前后局部能量至少低6 dB，映射后不覆盖完整原声片段、不以全黑结束；这只是数值筛查，AI仍须判断是否值得表现。黑场只覆盖落差，源声音恢复时画面也恢复，误差不超过1帧。
- `final_hit`：可选对象，填写 `source_time`（要求延后的实际攻击起点）、`reviewed: true` 与 `evidence`。按原片完整保留范围计算最后原声结束，要求该攻击映射时间不早于它。检测峰可能比真正攻击更晚，不能拿峰值代替起音门控。用户只要求最后重击时允许前段抬升；要求整个高潮时应使用更早的抬升起点。

音乐提示用源秒数映射进同一 BGM 时间线，再量化到 30 fps；修改镜头后重新检查末句。渲染器把黑场写入受影响分段，草稿使用相同分段副本，不是可单独拖动的黑色遮罩。原曲不会自动静音或变速，主动黑场必须引用上述静音副本。快切结束后先完整呈现剧情高潮，再按固定片尾流程使用 E−1.5 取帧时停，不尾接整集。

## 产物与复用

安装包适配：Python 旧 `export` 入口已禁用且不加载 NarratoAI 业务模块；下列正式导出、重复执行、索引备份与登记原则由本插件的 Node 原生导出桥贯彻。正文 runner 仅对指纹、源身份、正式分段和实际媒体完整匹配的已有中间片作只读恢复（`resumed:true`）；计划调整指纹不同时使用隔离的新正文输出，不覆盖或重新编码旧文件。同一产物不匹配仍须报错，由 AI 修复后再试，不伪装恢复成功。

- `《剧名》成片.mp4`：统一 1080×1920、30 fps、有原声音轨的成片；旧任务沿用 `宣传片.mp4`。方案及以下执行产物均在新任务目录的 `tmp/` 下。
- `tmp/plan.json`：唯一方案，驱动渲染与草稿。成片时补齐实际片尾数据；以前生成的任何文档保持原样。
- `tmp/render-result.json`：最终成片完整解码、实际总长、方案指纹及 DSH ending 描述，包含 PNG、完整 WAV、原生转场资源、正文 E 与源帧映射；正文中间结果另存，不能冒充最终验收。
- `tmp/dialogue-alignment.json`：逐台词记录实际使用的字幕或语音锚点及局部看帧的验收结果，可混合两种来源；其中 `segments` 只含已验收对白，不代替非对白视觉验收或整个执行计划。
- `sampling_file`：本任务持久化采样清单，保留真实窗口、帧率与证据，只用于对白；清单不放在可清理的 `tmp/work/`。
- `tmp/beats.json`：实际配乐的拍点分析，随最终方案保留。
- `tmp/export-result.json`：新草稿路径、登记状态、片段数量和未做界面播放验收的标记。
- `tmp/assets/`：成片与草稿仍需使用的正式生成素材，必须保留；DSH 的 `ending-*` 必须放在此正式目录，PNG、完整 WAV、原生效果副本和序列帧不能随临时文件清理。
- `tmp/root-meta-before-*.json`：导入前真实剪映索引备份，保留供恢复。
- `tmp/work/`：仅本执行器创建并标记的临时抽帧、分段编码与拼接列表，可用 `clean` 清理。

实际执行调整可在原任务中保存、同步和重新校验，计划指纹不同的正文使用新隔离输出，不覆盖旧正文。最终成片已存在时不会覆盖；成功后若要另做新版本，使用新独立任务，不改旧视频或草稿。原视频大小或修改时间改变后，旧索引不能用于导出，不能把源身份故障吞掉当作可用素材。

重复执行成功任务的 `export` 会返回已有草稿；导出器完成素材与封面后才登记根索引，保留旧条目和未知元数据。根索引读取失败或任务期间旧条目被移除时停止登记，不重建用户列表。

新草稿文件遇到临时访问拒绝时，原生文件写入最多原地重试 5 次；仍失败则停止并保留错误，不反复登记新草稿。
